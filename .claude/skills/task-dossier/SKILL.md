# 任务档案（分阶段开发 · 跨会话续接）

一个大任务对应一份活档案 `docs/tasks/<任务slug>.md`，从开工一直更新到收尾，不按日期另建快照。

## 开工评估（分析新需求、给方案时）

满足任一条就建议分阶段建档：

- 涉及 3 个以上模块，或改动面广
- 一个会话的上下文做不完
- 有明确的先后依赖（如模型 → 服务 → UI → 联调）
- 用户说是大功能 / 大改造 / 重构

需要时：

1. 说明「这个任务较大，建议用任务档案分阶段推进，避免跨会话丢进度」。
2. 给阶段拆分草案：每个阶段的目标、涉及文件、验收点、依赖。
3. 用户确认后按下方模板建档。档案只是方案，每个阶段写代码仍按 protocol-dev 等授权。

小任务不提，正常走 protocol-dev。

## 交接（用户要开新会话、上下文快满、说「交接」时）

不用用户详述，直接：

1. 更新「分阶段计划」的勾选（完成的打 `[x]`，附 commit SHA）和「进度台账」（做了什么、commit、改动文件、下一步从哪开始、遗留问题）。
2. 更新头部的状态和日期。
3. 单独用一个代码块给出续接启动词：

   ```
   读 @AGENTS.md 协议 + @docs/tasks/<slug>.md 任务档案，按档案「新会话启动指令」续接开发。
   ```

## 续接（用户说「继续 X」或贴启动词时）

读档案和它指向的关键文件，复述当前第几阶段、上次停在哪、下一步做什么，等授权再动手。

## 规则

- 写入、更新档案前先展示内容，等确认。
- 进度台账只追加，不删历史；计划的勾选可以改。
- 一个任务只用一份档案。memory 里的进度笔记只留一行指向档案，不重复写进度明细。

## 档案模板

```markdown
# 任务档案：<名称>

> 状态：进行中 / 已完成｜分支：`feat/xxx`｜创建：YYYY-MM-DD｜更新：YYYY-MM-DD

## 0. 新会话启动指令（AI 必读）
1. 读 `@AGENTS.md` 开发协议
2. 读本档案全文
3. 复述「当前阶段 + 上次停点 + 下一步」，等授权再动手

## 1. 目标与验收标准
- 目标：一句话
- 验收：如何判定整体完成

## 2. 分阶段计划
- [x] 阶段1 <名>：<目标> — 完成（commit `abc1234`）
- [ ] 阶段2 <名>：<目标> — 待做｜依赖：阶段1

## 3. 架构与上下文
- 关键文件：`路径` — 作用
- 技术决策：…
- 参考文档：`路径` — 说明

## 4. 进度台账（每次会话末追加，倒序）
### YYYY-MM-DD（会话N）
- 做了：…
- commit：`SHA` <msg>
- 下一步：从 `文件:行` 起，做 …
- 遗留/坑：…

## 5. 决策与坑记录
- …
```
